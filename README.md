# Online Learning Project

## Описание

Проект Online Learning Project представляет собой бэкенд-приложение для системы онлайн-обучения с кастомной авторизацией по Email и полноценным REST API для управления курсами, уроками, подписками и приёмом онлайн-платежей.

## Технологии

*   **Backend:** Python / Django / Django REST Framework (DRF)
*   **Database:** PostgreSQL (хранение данных и истории отправок)
*   **Dependencies:** Poetry (управление пакетами и виртуальным окружением)

## Интеграция эквайринга Stripe

В рамках последнего обновления в систему была интегрирована возможность онлайн-оплаты курсов через **Stripe API**.

### Ключевые особенности реализации:
1. Вся логика взаимодействия со Stripe вынесена из контроллеров в сервисный модуль (`services.py`). Функции общаются с внешним API и возвращают структурированные JSON-словари.
2. Секретные ключи (`STRIPE_SECRET_KEY`) инициализируются на стороне бэкенда.
3. Расширена существующая модель `Payments` в приложении `users`. Добавлен новый способ оплаты (`stripe`), поля для сохранения ID сессии, ссылки на оплату и статуса транзакции (`open` / `complete` / `expired`).
4. Реализован эндпоинт для проверки транзакций. Сервер обращается к Stripe API, верифицирует факт списания виртуальных денег и обновляет статус в локальной базе данных проекта.

## Архитектура эндпоинтов оплаты (Приложение `users`)

Все финансовые эндпоинты требуют обязательной JWT-авторизации (передачи токена в заголовке `Authorization: Bearer <token>`).

### 1. Инициализация покупки и генерация ссылки
* **URL:** `/users/payments/`
* **Метод:** `POST`
* **Тело запроса (JSON):**
  ```json
  {
      "paid_course": 2
  }
  ```
* **Логика работы:** Контроллер динамически подтягивает цену из модели `Course`, после чего последовательно вызывает три обязательных этапа Stripe API:
  1. `stripe.products.create` — Регистрация курса как продукта.
  2. `stripe.prices.create` — Создание цены.
  3. `stripe.checkout.sessions.create` — Генерация платежной сессии Checkout.
* **Успешный ответ (`201 Created`):**
  ```json
  {
      "id": 5,
      "paid_course": 2,
      "payment_amount": "5000.00",
      "payment_type": "stripe",
      "payment_link": "https://stripe.com_...",
      "status": "open",
      "created_at": "2026-07-01T00:19:40.790813+03:00"
  }
  ```

### 2. Просмотр истории платежей текущего пользователя
* **URL:** `/users/payments/`
* **Метод:** `GET`
* **Поддерживаемый функционал:** Постраничная пагинация, фильтрация по полям `paid_course`, `paid_lesson`, `payment_type`, а также сортировка по дате создания (`ordering=-created_at`).

### 3. Проверка и синхронизация статуса платежа
* **URL:** `/users/payments/status/<int:pk>/`
* **Метод:** `GET`
* **Логика работы:** Контроллер извлекает сохраненный `session_id`, делает запрос к эндпоинту `stripe.checkout.sessions.retrieve`, перезаписывает статус в локальной БД и отдает развернутый отчет:
  ```json
  {
      "payment_id": 5,
      "course": "Основы Django REST Framework",
      "amount": "5000.00",
      "stripe_status": "complete",
      "payment_status": "paid"
  }
  ```

## Основные эндпоинты API (Маршруты)

### Пользователи (`/users/`)
* `GET /users/profile/<id>/` — Просмотр профиля пользователя (включает полную историю его платежей, информацию об оплаченных курсах и уроках).
* `PATCH /users/profile/<id>/` — Частичное редактирование профиля (город, телефон, аватар).
* `GET /users/payments/` — Просмотр списка всех платежей в системе (доступна фильтрация и сортировка).

### Курсы и Уроки (`/learnings/`)
* `GET /learnings/courses/` — Получить список всех курсов (с вложенными уроками и общим количеством уроков через `SerializerMethodField`).
* `POST /learnings/courses/` — Создать новый курс.
* `GET /learnings/lessons/` — Получить список всех уроков.
* `POST /learnings/lessons/create/` — Создать новый урок (требуется передать `course` id).
* `PATCH /learnings/lessons/update/<id>/` — Редактировать урок.
* `DELETE /learnings/lessons/delete/<id>/` — Удалить урок.

### Фильтрация и Сортировка

Для списка платежей (`/users/payments/`) подключен `django-filter` и настроена фильтрация по связанным объектам (через их первичные ключи `id`), а также сортировка.

**Доступные параметры фильтрации:**
* По курсу: `?paid_course=<id>`
* По уроку: `?paid_lesson=<id>`
* По способу оплаты: `?payment_type=cash` (или `transfer`)

**Доступные параметры сортировки:**
* По дате оплаты (от старых к новым): `?ordering=payment_date`
* По дате оплаты (от новых к старым): `?ordering=-payment_date`

### Ролевая модель и управление правами доступа (DRF Permissions)
В проекте реализовано разграничение прав доступа между типами пользователей на основе кастомных классов прав (`DRF Permissions`), встроенных механизмов аутентификации и групп Django.

### Подписки (APIView)
* `POST /learnings/subscribe/` — Управление подпиской. 
  **Тело запроса (JSON):**
  ```json
  {
      "course": 2
  }
  ```
  *При первом запросе подписка создается (ответ: `"Подписка добавлена"`), при повторном — удаляется (ответ: `"Подписка удалена"`).*

**Натройка ролей в проекте:**

1. **Обычный пользователь** — имеет доступ только к собственному учебному контенту и своему профилю. Может просматривать только общую инфо о других пользователях.
2. **Модератор** — пользователь, состоящий в группе `moderators` (назначается через панель администратора). Обладает расширенными правами на просмотр и редактирование, но ограничен в управлении контентом (не может добавлять/удалять уроки и курсы).
3. **Администратор (Суперпользователь)** — полный доступ ко всем функциям системы и удалению аккаунтов.

### В проект были интегрированы следующие ключевые возможности
1. **Система подписок на курсы (`APIView`):**
   - Реализован эндпоинт-переключатель для подписки/отписки авторизованных пользователей на обновления конкретных курсов.
   - В сериализатор курса добавлено динамическое вычисляемое поле `is_subscribed`, отображающее статус подписки текущего пользователя.

2. **Валидация контента (`Validators`):**
   - Создан кастомный класс-валидатор `YoutubeOnlyValidator`.
   - Запрещено добавление любых сторонних ссылок (в поле видео уроков и текстовые описания курсов/уроков), кроме `youtube.com`.

3. **Пагинация (`Pagination`):**
   - Настроен постраничный вывод списков в файле `paginators.py`.
   - Для курсов установлено ограничение в 5 элементов на страницу (`CoursePagination`), для уроков — 10 элементов (`LessonPagination`).
   - Поддерживается динамическое изменение размера страницы клиентом через query-параметр `?page_size=`.

4. **Полное покрытие тестами (`APITestCase`):**
   - Написаны комплексные тесты для всех имеющихся эндпоинтов (CRUD курсов, CRUD уроков, логика подписок, валидация и разграничение прав доступа для модераторов).

## Развертывание ролей и фикстур
Все права группы модераторов зафиксированы в фикстуре проекта. Для развертывания проекта на новом окружении выполните шаги:

1. Загрузите готовую структуру группы модераторов со всеми правами из фикстуры:
   ```
   python manage.py loaddata groups.json
   ```
3. Создайте суперпользователя для доступа в админку:
   ```
   python manage.py createsuperuser
   ```
4. Перейдите в панель администратора по адресу `http://127.0.0.1:8000/admin/`, выберите нужного пользователя и добавьте его в группу **`moderators`**, чтобы наделить его правами модератора для тестирования в Postman.

## Установка:

1. Клонируйте репозиторий:
```
git clone https://github.com/AlexanderKokorinV/Online_Learning_Project.git
```
2. Установите зависимости:
```
poetry config virtualenvs.in-project true --local
poetry install
```
3. Конфигурация переменных окружения
Создайте в корневом каталоге файл **`.env`** и заполните его по образцу:
```
# Создайте файл .env из копии этого файла и замените значения переменных реальными данными
SECRET_KEY=my_SECRET_KEY #Ваш_SECRET_KEY
DEBUG=True

# Конфигурация базы данных
DB_NAME=my_data_base # Имя базы данных
DB_USER=username # Имя пользователя (например, postgres)
DB_PASSWORD=password # Пароль базы данных
DB_HOST=localhost # Хост для базы данных
DB_PORT=5432 # Номер порта, который закреплен за PostgreSQL по умолчанию
```

4. Подготовка базы данных и миграции:

Перед запуском проекта убедитесь, что на вашем компьютере установлена и запущена СУБД **PostgreSQL**.
Создайте пустую базу данных, например, online_learning.

Выполните миграции Django для создания таблиц:
```
poetry run python manage.py makemigrations
poetry run python manage.py migrate
```

5. Создание суперпользователя (Администратора)

Создайте аккаунт администратора для доступа в панель управления. В качестве логина система запросит **Email**:
```
poetry run python manage.py createsuperuser
```

6. Запуск сервера разработки
```
poetry run python manage.py runserver
```

## Тестирование

Все эндпоинты успешно протестированы через **Postman**. Запросы выполняются без авторизации (на текущем этапе разработки).
